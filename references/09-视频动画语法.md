# 09 · 视频动画语法：YouTube 解说 / 科技 / AI / 财经片的 8 种画法

做口播解说片的「动画段」时读这份。它是 8 张语法卡（`references/动画语法/`）的总目录、选型表、跨语法规律、库速查，以及给口播管线用的片段契约。

8 种语法都有可直接渲的示范片（`scripts/engine/demos/<语法>/`，收进来时和实验原片逐像素一致；2026-10-05 修了 `TY.charsIn` 透明度后，y1 示范片标题按原意 0.55s 淡出，那 0.55s 的帧和原片不同）和参数化片段（`scripts/engine/clips/<语法>.js`，喂一份 JSON 就出一段时长精确的视频）。

## 二、怎么为一段口播选语法

先看这段口播在干什么，再选画法。一支片子可以分段换语法，但同一段里不混。

| 这段口播在…… | 选 | 别选 | 为什么 |
|---|---|---|---|
| 讲一个概念、一个机制（「神经网络是怎么……」） | **t1 3b1b**（要推导、有公式）或 **y1 Kurzgesagt**（要尺度、要可爱） | y2（没有真实材料可贴，会变成假档案） | 机制靠形变和尺度讲得清 |
| 讲新闻、事件、历史，有截图和原话 | **y2 Vox** | y1（扁平卡通冲淡可信度） | 观众要亲眼看到出处 |
| 讲自己的经历、翻车、笑点 | **y4 storytime** | t2（自带好消息的情绪） | 笑点在反应镜头的停顿里 |
| 讲清单、几个要点、几个阶段、一句金句 | **y5 动态文字** | t1（没有能变形的对象） | 信息是结构，不是画面 |
| 讲产品、教程步骤、功能、参数 | **t2 发布会界面**（截图满幅并推近；玻璃卡可选） | t1（玻璃和光斑不承载逻辑，反过来也一样） | 一屏一件事、名词和数字当主角 |
| 讲数字、增长、走势、对比 | **t3 财经图表** | t2 的大数字（只有一个数时才用它） | 要坐标系和单位，要能被较真 |
| 边讲边推导、一步一步论证 | **y3 白板** | 一次整屏切换 | 说一句写一句，最后拉远是落点 |

两条兜底：
- 有真实截图要放 → t2（教程，干净）或 y2（论证，证据感）。截图当主画面、尽量满幅，一律等比放，不裁关键 UI。
- 一段里只有一个数 → 不画图表，用 t2/y5 的大数字计数，在口播说出数值那一刻落定。

## 三、跨语法通用规律

从 8 张卡里提炼的、换语法也成立的规矩。每条后面是出处。

1. **相机只由时间决定，场景按相机矢量重画。** 推拉、平移、穿越都是同一个世界画布在不同相机下重画，所以放大 60 倍也不糊，转场里上一镜继续按时间推相机（`zoomThrough` 的 `live:true`）。（y1 ⑥「关键架构」；y3 ⑥；t1 ④-2）
2. **缩放用对数插值，穿过圆形开口要够倍数。** `CAM.zlerp` 让每帧放大同样的倍数，线性插值会前慢后猛；穿进半径 r 的开口，倍数 ≥ 开口中心到最远屏幕角的距离 / r（居中时约 1100/r，`CAM.coverZoom`）。（y1 ⑧-2；t1 ④-2）
3. **揭开那一帧对齐拍点或口播词。** 转场从新段起点开始算，要让新画面露出来的那一帧落在小节线上：段起点 = 小节线 − 揭开点 × 转场时长（`MO.onBeat`）。数字要在口播说出数值时落定：计数起点 = 说数字的时刻 − 计数时长。白板开写比对应短语晚约 0.5s。（y5 ④「对位技巧」；t2 ⑤；t3 ⑤；y3 ⑤）
4. **先结构、后数据、最后标注。** 坐标系先出、数据后长、标注最后，一镜只标一件事；3b1b 是先 Write 问题再演示；发布会是眉题→产品名→副标题。（t3 ③；t1 ⑤；t2 ③）
5. **一屏一个焦点。** 同一时刻只让一个东西入场，其余静止；主词和辅句至少 3:1；背景的饱和度、对比、线宽都比主角低一档。（y5 ⑧-1；t2 ⑤；y4 ⑧-2）
6. **入场慢、退场快，落定后要停。** 入场 0.3–0.4s、退场约 0.18s；数字落定后至少停 0.5s，包袱后定住 ≥0.9s，3b1b 每个动画后 wait 约 1s。（y5 ⑤；t3 ⑧-3；y4 ⑤；t1 ⑤）
7. **动在事件上。** 解说类片子的运动是脉冲：停住 → 快推、横移或砸入 → 停住。快推 0.28 秒推近 18–32% 后停；同倍率横移 0.30 秒（同一面「墙」上从一件证据移到下一件）；砸入 0.17 秒（1.55→0.94→1.0）；停多久按口播。引擎里现成：`CAM.track`（镜头动作表）、`MO.slam`（元素砸入），时长常量在 `MO.PULSE`；8 个参数化片段都已按这个节奏动，没有内置的匀速慢推和呼吸。不用匀速慢推、全员浮动呼吸来凑运动：同一份分镜、同一批素材，每镜匀速推近 7.5% 的版本被判「像在放 PPT」，换成停住 → 0.28 秒快推 → 停住之后被认可，完全静止的帧反而从 16% 升到 72%。环境层（Kurzgesagt 的星闪、粒子）可以一直轻轻动；storytime 七成帧完全静止，生命在快切＋定住。艺术风格速通是另一回事，画要一直活（见 04 号）。（y1 ③、⑧-1；y4 ⑧-1；t2 ③）
8. **两层帧率：相机平滑，元素步进。** Vox 相机平滑、纸片/荧光笔/打字按 12fps 一拍二；storytime 角色 24fps、镜头 60fps。全部丝滑像企业宣传片，全部步进会晃。（y2 ③、⑧-1；y4 ③）
9. **颜色＝概念，强调色少。** 一个颜色讲一个概念（公式里的 W 和连线同是蓝），超过 3–4 种语义色就记不住；Vox 是黑、纸白、一种红，白板是黑加一个橙。（t1 ⑧-3；t3 ⑧-2；y2 ⑧-3；y3 ⑧-3）
10. **转场放在换气和换话题处，不放在句子中间。** 甩镜切在两句之间，反应镜头放在沉默里；白板的平移卡新论点；Vox 硬切卡句读。（y4 ⑤；y3 ⑤；y2 ④）
11. **审片要查逻辑和数字口径，不只看好不好看。** 实测抓到过的：「涨了 8.7 倍」应为「涨到原来的 8.7 倍」；展开成全屏后又从 0 重数；讲隐藏层却连到了像素；倍数要能从图上的数算出来。（t3 修订表；t2 修订表；t1 ⑥）
12. **真实素材当主画面，保持原样。** 有截图、照片、录像、原文就让它满幅或接近满幅，推近到要讲的那块，代码只做解释、标注和运镜（`MD.cover` 满幅＋焦点＋推近，`MD.print` 冲印件，`MD.label` 黑底撕边标签；参数化片段 t2 的截图卡、y2 的照片默认就是满幅或占画面八九成）；截图等比放、不裁关键 UI；数据只改「怎么出现」不改「是多少」；柱一律从 0 起，轴不从 0 起要写明；虚构数据每一镜标「示意数据」，真实数据不许出现这个角标。（t3 ②、⑧-1；片段契约）

引擎相关的小改动：竖屏整片 `render.py --film <名> --width 1080 --height 1920`（或在 eras.js 写 `window.FILM_SIZE = [1080, 1920]`），引擎、转场、相机和各库按当前画布算，35 种艺术风格场景仍只按横屏画过；段的 `clip`（视频帧序列）默认等比铺满，写 `clipDraw(c, frame, lt, t)` 自己摆（推近、焦点、冲印件），帧或图片缺失直接报错、拒绝渲染；段可写 `dur`（秒）代替 `eighths`；`window.BPM` 改节拍；解说片写 `window.PUNCH = 0` 关掉拍点冲击（或单个转场写 `punch`）；`window.SCENE_LIBS / SCENE_DIR` 让一支片子把代码放在自己的目录里（demos 就是这么组织的）。

**实验时的旧名 → 现在的名字**（读实验归档代码时对照）：`YT.camAt→CAM.at`、`YT.camForAnchor→CAM.anchor`、`YT.apply/camera→CAM.apply/with`（相机字段 `zoom/rot` 改成 `z/r`）、`YT.ease.*→MO.*`、`YT.spring(t,f,d)→MO.springHz`、`YT.textIn→TY.charsIn`、`YT.type→TY.typed`、`YT.partial→DG.drawPartial`、`YT.at→DG.pointAt`、`YT.circlePts→DG.ellipsePts`、`YT.paperTile/halftone/tornEdge→CL.*`、`YT.bean/POSES/mouth→TOON.*`、`MN.*→DG.*`（`lerpPts→morph`、`C→MANIM`、`FONT_RM→FONT.rm`）、`GL.*→UI.*`、`MO.textIn→TY.blurIn`、`MO.count/fmt/tabular→TY.*`、`easeOutQuint/easeOutExpo→quintOut/expoOut`、转场 `k_lens→lensReveal`、`k_fill→matchCut`、`hardcut→cut`、y5 的 `zoomThrough→fillZoom`（和 3b1b 的镜头穿越撞名）。

## 五、片段契约（给口播管线的「动画段」）

口播视频管线（无论你用哪套）在合适的段落调用这 8 种语法做动画段，由管线当导演选语法、从口播词级时间戳算 cue。这一节是双方的约定。

### 入口

**口播管线里建议包一层脚本，不要手敲下面这些**：draft 从成片时间轴定时长、出词表和 spec 草稿 → render 解析 word、调本节的 render.py、数帧、换进剪辑工程、冻结 → verify 对章节逐帧核同步。作者自己的管线就是这样接的（那部分未随本仓库开源）。下面是引擎本身的接口。

```sh
cd <skill>/scripts
uv run --with playwright python engine/render.py --spec clip.json --out 片段.mp4            # 无声 H.264 yuv420p
uv run --with playwright python engine/render.py --spec clip.json --alpha --out 片段.mov    # ProRes 4444 带透明（不画背景，给管线叠层）
uv run --with playwright python engine/render.py --spec clip.json --stills 0.5,2,4 --out 静帧/   # 抽帧检查
# 预览：本地服务打开 scripts/engine/clip.html?spec=examples/t3_finance_chart.json 拖时间轴
```

- 时长严格等于 `duration`：帧数 = round(duration × fps)，第 i 帧的时间是 i / fps。H.264 每秒一个关键帧（GOP = fps），管线的渲染器按秒 seek 不冻帧。
- **单个片段最多撑 8 秒。** `duration` 超过 8 秒时 render.py 在开头和结尾各打印一次醒目警告，不报错（口播管线里有合法的长片段）。一个片段撑太久会读成一页 PPT：一个版式到底、要点越堆越长、背景从头死到尾。一支片要拆成多镜，每镜一个 spec（或一段 scenes），镜与镜换语法或换做法，再拼接（SKILL.md 轨道档第 3–4 步、`references/镜头表模板.md`）。样例 spec 有 8.5–10 秒的，那是一段的写法示范，不是一支片的长度。
- 宽高和 fps 从 spec 读，默认 1920×1080@30；竖屏写 `width: 1080, height: 1920`（或命令行 `--width 1080 --height 1920` 覆盖 spec），每种语法都有竖屏排版。
- spec 里的素材路径相对 spec 文件（也可以写绝对路径）；render.py 只服务 spec 里点名的文件。认这些字段：`cues[].image`、`cues[].frames`（录像帧序列：一个目录或路径数组）、`data.image`、`data.character`（y4 帧库目录）。路径怎么解析见 `engine/spec_assets.py`。
- 量这一段：`uv run qa.py --spec <clip.json>`（在 `scripts/` 下；整段当一段量确定性、运动、静止帧对、孤立跳变、耗时，竖屏按画幅缩；短于 0.35 秒的单调快推、横移、砸入记作镜头事件，不算跳变）。
- 交付：`uv run deliver.py 片段.mp4 --spec <clip.json> --out output/`。先过门禁 `film_gate.py`（快速运动帧占比 < 0.035 红灯，不复制、非零退出），过了才复制并写 `交付说明.md`，事实段由脚本写。门禁是在 1–2 分钟的成片上标定的，10 秒以内的片段数值噪声大；片段要拼进成片的，在成片上跑 deliver.py。
- 页面报错（语法文件出错、图片或视频帧不存在）→ 非零退出，不出片。`qa.py --spec` 和 render.py 用同一套素材解析（`engine/spec_assets.py`），`frames` 和角色帧库都认。spec 里有字库没有的汉字只告警（会回退系统字体，换台机器会变样），常用字都在子集里。

### spec

```json
{
  "grammar": "t3_finance_chart",          // 8 选 1：t1_3b1b | t2_keynote_ui | t3_finance_chart | y1_kurzgesagt | y2_vox | y3_whiteboard | y4_storytime | y5_kinetic_type
  "duration": 7, "fps": 30, "width": 1920, "height": 1080,
  "safe": { "top": 0, "bottom": 520 },     // 可选：让开的边（px），见下
  "alpha": false,                          // 可选：true = 不画背景（render.py --alpha 会自动设上）
  "data": { ... },                        // 语法级参数，各语法认的字段见下面每节的「data」行；不认的字段直接忽略
  "cues": [ { "at": 1.2, "kind": "bar", "text": "...", "sub": "...", "data": { ... }, "image": "截图.png", "dur": 1.0 } ]
}
```

**cue 的公共字段**（每种语法认哪些见下面各节）：

| 字段 | 含义 |
|---|---|
| `at` | 秒，必填。「揭开那一帧」：元素在 t = at 这一帧第一次可见（动画内部从 at 前一帧起算）。例外：`number` 的 at 是数字**落定**的时刻。cue 不必按时间排序，clip.js 会排；at 超过 duration 的 cue 告警后丢掉（看不到，也不占版面）。 |
| `kind` | 必填。**写了这个语法不认的 kind 不报错、什么都不画**——对着下面的表写。 |
| `text` | 主文字：标题、要点、标签、气泡原文、插入镜头的大字。 |
| `sub` | 辅文字：t2 卡片说明、y5 辅句、y4 气泡里实际显示的短句、y4 插入镜头里他打的那一行。 |
| `image` | 图片路径，相对 spec 文件（也可写绝对路径、`data:`、`http(s):`）。文件不存在 → 拒绝渲染。 |
| `frames` / `fps` / `loop` | 录像帧序列（t2 的截图卡、y2 的照片认）：一个目录（按文件名排序取 png/jpg/webp）或路径数组；从 at 起按 `fps`（默认 30）播，播完停在最后一帧，`loop: true` 循环。版式按第一帧定。缺帧 → 拒绝渲染。 |
| `data` | 这个 cue 自己的参数（`index`、`rect`、`icon`……），见各节。 |
| `dur` | 只有少数 kind 读：t1 的 title/point/equation/line，t3 的 bar/line/candle，y1 的 enter，y4 的 react/insert。其它 kind 写了也不读。 |

**`safe`**：`{top, bottom, left, right, fill?}`（px，默认 0）。clip.js 把它和让开后的内容框 `ctx.box = {x, y, w, h}` 传给语法；`fill` 是可选颜色，渲完把让开的边涂成它（竖屏片里让图表成为和相邻 contain 截图同一位置、同一种底的「卡」；`--alpha` 时不涂）。**8 种语法都已接 `top` / `bottom`**（语法对象里都写了 `safe: true`，内容只排在 top..H−bottom 之间：t3 的坐标系与来源行、y2 的相机缩放与画面中心、t1/t2/y1/y3/y5 的版面、y4 的气泡与插入镜头大字）；**`left` / `right` 目前没有语法按它排版**，写了只会被 `fill` 涂色、内容照样排到边上。竖屏 1080×1920 的口播片字幕带约在 1400–1520，`bottom` 取 490–570；横屏一般 `bottom` 160–220。新语法要接 safe，照 t3：版式的纵向基准加 `safe.top`、底部元素减 `safe.bottom`，或者直接按 `ctx.box` 排，再在语法对象里写 `safe: true`（没写而 spec 给了 safe 时 clip.js 会 console.warn）。

**`number`（大数字）的口径**——只有 t2、t3、y5 认，其它 5 种写了不显示：

| 项 | 规定 |
|---|---|
| 数值 | `data.value`（数，可负；不写当 0）。从 0 滚到 value（expoOut，先快后慢），负数用真减号「−」，整数部分自动加千分位。 |
| 格式 | `data.prefix`（如 `"¥"`）、`data.suffix`（如 `"%"`、`" 倍"`，要空格自己写）、`data.decimals`（默认 **0**；t3 的 `spec.data.decimals` 只管柱子标签，**number 不继承**，要小数就在 cue 里再写一遍）。 |
| 说明 | 写 `text`、`sub`、`data.text` 任一个都行，clip.js 把三者统一。 |
| 小标签 | `data.label`：t2 画在数字上方，y5 画在页左上；t3 不画。 |
| 时间 | `at` = 数字落定的时刻。t2、t3 在 at−0.9s 开始滚；y5 在 at−0.7s 换页并开始滚。所以 number 的 at 至少写 0.9（y5 0.7），否则第 0 帧就已经滚了一大半。 |
| 位置 | t2：单独一屏，上一屏在 at−0.9s 开始退场，不叠在卡上；t3：图区上方专留的一条，右对齐，说明在数字左边；y5：单独一页。 |

### 各语法认的 cue

下面每节第一行是 spec 级 `data`，表里是 cue。「最小 spec」是能渲出一段像样画面的最少写法，复制的是结构，内容按你的题材换；第一个 cue 都是画面事件，不是标题。

#### t1_3b1b（3b1b / manim 讲解：公式、曲线、要点）

### 给管线导演的提醒

- 一段动画别塞太多 cue：按第一节的镜头时长，3–8 秒的片段放 2–5 个 cue 最舒服；cue 太密，写字会被迫提速、相机来不及到位。
- **写 spec 的三条底线**（翻页式 PPT 多半从这里来）：第一个 cue 是画面事件（曲线、截图、数据长出、钻入、图标、屏幕特写、数字砸入），不是第 0 秒的 title；文字类 cue（title、point）不超过一半，同一个 kind 不连续出现 3 次；每条上屏的 `text`、`sub` 不超过 14 个字，口播原文交给字幕（y4 写了 `sub` 时 `text` 只定张嘴时长、不上屏，不受此限）。
- 画面里有字的语法（t1/t3/y3/y5）会和管线的烧录字幕抢视线，叠层时把字幕挪开或这段不烧。
- 透明模式（`--alpha`）只去掉背景层，元素本身的阴影还在；y2 的纸片、t2 的玻璃卡在透明底上读作「浮在画面上的卡片」。t3 是白纸黑字，透明底下字带一圈白色光晕，叠深色画面也读得清；t1 的白字带深色光晕。
- **竖屏里贴截图，要框口播正在念的那半句。** 竖屏桌面上一张截图约 900px 宽，网页里 16px 的正文要推近 2–2.5 倍才看得清；框住整段宽字（框宽接近画宽）时红圈放不下，镜头就推不进去。一句话跨两行就拆成两个 highlight，各对一个关键词（2026-10-04 实测：拆开后推近 2.4 倍，字高约 50px）。rect 目测常偏 20–30%，先 `--stills` 渲一张核。
- **语法文件里的步进动画要从 at 起算。** 「一拍二」之类的步进如果按绝对时间网格取整（`MO.step(t, 12)`），元素会比 at 早最多一格露出（30fps 下早 2 帧）。写成 `MO.step(t − at, 12)`，at 这一帧才是第一帧。y4 的角色帧仍按绝对 24fps 取，cue 落点可能差 1 帧，用前先核。

## 七、踩过的坑

- **（2026-10-04 接入口播管线实测）y2 推近后下一处框在画外，荧光笔在画外开扫。** 观众晚 7 帧才看到。已改：框的起点不在当前镜头里时，镜头先移过去、at 前一帧到位，再揭开；推近的倍数同时受「红圈留在画里」约束（红圈比框宽 1.24 倍、高 1.5 倍）。
- **（2026-10-04 参数化片段审片）t3 刻度撒谎、类目没名字、大数字压线头。** `fmtTick` 只在步长 <1 时留小数，步长 2.5 时 −2.5/2.5/7.5 被印成 −3/3/8；10 根类目柱竖屏按 `ceil(n/6)` 抽稀，被标注的「第一」恰好没名字；number 固定在图区右上角，上涨的折线线头正好在那。三处都改了（见第五节 t3 一行）。
- **（同上）y2 文字卡没打完相机就走。** 相机离开只看下一件的 at−0.95。现在按「打完＋停 0.5s」才起跑（最晚 at−0.4），间隔短就把打字从 13 字/秒提到最多 40 字/秒。
- **（同上）普惠体 Medium/Bold 的全角空格字宽是 0。** 源字体（阿里巴巴普惠体 3.0 的 65/85 两个字重）本身就是 0，「美元　纵轴未从 0 开始」粘成一串。`font_subset.py` 抽子集时自动设成和「一」同宽；已有文件用 `--fix-widths` 修过。
- **（同上）t3 竖屏的标注正好落在烧录字幕带上。** 竖屏图表底部在 y≈1660，标注在 y≈1460，和 1080×1920 片子的字幕（1400–1520）重叠。加了 `safe`。

- **（2026-10-05 参数化片段终审）照样例写都对，换成竖屏和真实长度就出画。** 独立终审 33 份 spec（横屏样例、自写竖屏、压力、边界、alpha）查出 12 条 🔴：y2 空 text 让渲染器死循环卡住；y5 深蓝页荧光笔和黄字同色把主词涂没、竖屏长数字出画；t1 竖屏 7 条要点压进字幕带；t3 竖屏副标题与来源行出画、标注压邻柱、透明底叠深色看不见；y1 竖屏标签被切；y3 竖屏说明出画；y4 竖屏打字溢出气泡；t2 同一时刻先后渲差 1 色阶（复用的缓冲带上一帧残留）。另自测出 `TY.charsIn` 不乘外层透明度（y1 标题说好的淡出是一帧消失）、t3 最低负数柱的数值压类目名、`TY.fit` 只数行数不量行宽。规律：**凡是「放不下」的地方都要有退路——先缩、再折、再让位，最后才告警**；只在样例长度上调好的版式，一碰真实口播就破。

- **两组实验各写了一个 `window.YT`，API 完全不同。** 合并时按功能拆成 8 个命名空间，并给同名不同义的东西改名：G2 的 `zoomThrough`（冲进色块）→ `fillZoom`，G2 的 `spring(t, freq, decay)` → `MO.springHz`，G1 的 `circlePts`（开口椭圆）→ `DG.ellipsePts`。
- **woff2 字体过不了字形检查。** 引擎的 `U.loadCmaps` 只会解 WOFF1／TTF，G3 的 woff2 一加载就 console.error，qa 判失败。收进来时统一转成 woff。
- **全片时间读出来的背景会因为片子在时间轴上的位置不同而换相位。** 发布会示范的光斑原来排在 8–16s，单独成片后构图全变了，用 `T2.PHASE = 8` 保住定稿画面。参数化片段里光斑只读片段时间，不受这个影响。
- **刻度要把数据整个包住。** `CH.ticks` 只给区间内的整刻度，最大值 130 时最高刻度可能是 100，柱子顶出坐标系；片段里补齐了上下各一档。
- **系统字体不在 skill 里。** Vox 示范的宋体（Songti SC）、动态文字示范的代码字体（Menlo）用的是 macOS 系统字体，换台机器会变样；参数化片段已全部换成 skill 自带的字体。
