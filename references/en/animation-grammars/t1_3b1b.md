# t1_3b1b · 3Blue1Brown-Style Math / Concept Visualization

[中文](../../动画语法/t1_3b1b.md) · **English**

> One-line grammar: **Put only "the one thing being explained right now" on a black background, morph (Transform) the previous concept directly into the next, color = concept name, almost no cuts throughout.**
>
> Demo film: `scripts/engine/demos/t1_3b1b/` (render: `render.py --film demos/t1_3b1b`) (8 s, 3 shots) · Overview `assets/动画语法/t1_3b1b_总览.jpg` · Code `scripts/engine/demos/t1_3b1b/`

## Pre-flight checklist

1. **Write out "who becomes what" for every shot.** What is the previous object and what is the next (grid → circle, one curve → another, pixel → neuron)? If you can't name the morph subjects for a sentence, don't use t1 — switch to y5 or y3.
2. **First frame is the object.** Axes, grids, curves appear first; titles and formulas arrive later. Don't Write a title line at second 0.
3. **Count on-screen text.** At any moment, no more than 2 key points on screen; before a third appears, the earlier ones must either become graphics or be taken away. Writing points as a list one by one is just black-background PowerPoint.
4. **Define the color table first.** One color per concept; the symbol in the formula and its corresponding object in the scene share that color. No more than 4 semantic colors in the whole film.
5. **Hold still on wait.** No constant-speed slow-push, breathing, or floating; the camera moves only when a new object needs to be seen, then stops (see ③ "camera").

## ① When to use

- **Use it**: when explaining how a mechanism "transforms step by step into something else" — neural network forward pass, attention, matrix transformation, gradient descent, probability distributions, algorithm flow. Voiceover with **action-verb sentences** like "we flatten this grid into a column" or "each pixel is multiplied by a weight" is the best fit: each sentence maps to one Transform.
- **Use it**: when the audience needs to "see the math" — the symbol in the formula corresponds one-to-one with the object in the scene (formula's W is blue, and the connecting lines are blue too).
- **Don't use it**: product launches, emotional/brand films (black background + white lines is too cold, too slow); real data trends (that's t3's job); voiceover that is opinion, story, or a memorable line (nothing to "morph" — forcing it leaves only decoration). Fast cuts under 8 s are also wrong — 3b1b's native rhythm is one animation 1–3 s + pause 1 s (see ⑤); squeezing to 8 s with 3 shots is already the upper limit.

## ③ Motion

- **Easing**: default `smooth = 6t⁵−15t⁴+10t³` (3b1b version: zero velocity and acceleration at both ends; CE version is sigmoid, `MO.smoothCE`). **Almost all animations use it**; linear is only for Write, constant-speed rotation, ShowPassingFlash advancement. `there_and_back` for Indicate, `rush_into/rush_from` for "charge in/out."
- **Default duration**: Animation run_time = 1 s, wait = 1 s. 2023–24 source-code stats: most common explicit run_time is 2 s (481 times) > 3 s (333) > 1 s (187) > 4 s (145).
- **LaggedStart**: default lag_ratio 0.05; most common in source code is 0.1. Implementation: `MO.lagged(i, n, p, r)` (the i-th item occupies `[i·r, i·r+1]`, total duration `1+(n−1)r`). This film: 100 pixels → neurons use 0.01 (1.1 s total), 160 edges use 0.006.
- **Write**: linear; <15 sub-objects → 1 s, otherwise 2 s; inter-sub-object lag = `min(4/(n+1), 0.2)`; each character "traces outline first, then fills" (`DG.math`/`DG.write`: lineDash advances stroke → fill fades in over last 60%, stroke fades out).
- **Transform**: resample both shapes to the same point count, **align starting points** (both start from upper-left, clockwise), interpolate point-by-point along straight lines (path_arc=0) + color interpolation. `DG.rectPts/circlePts/morph`. This film: grid → circle (pixels → neurons), weight grid → fly into one neuron (weighted sum).
- **Entrance/exit**: FadeIn/FadeOut with shift (this film 24–40 px, "bottom-up" or "fade upward"); new layer of neurons fades in from 24 px to the right; replaced objects shrink to a point and merge into "⋮."
- **Signal**: ShowPassingFlash (time_width 2) — copy the edge, tint it yellow, line width ×1.5, visible segment `[max(0,u−2), min(1,u)]`, u from 0 to 3 (`DG.flash`), staggered by input row lag 0.04.
- **Camera**: MovingCameraScene frame animation; camera movement is an event: hold still → push to the next object to examine → hold still. Default push uses 3b1b's native smooth in one move (≈1 s, `CAM.track`'s push/to); punch-in only at the conclusion beat (0.28 s push-in 18–32%, emphasis, once or twice per segment); 3D orbit 0.5–3°/s (3b1b default 1°/s) only when explaining spatial relationships. In this film, shot 2 pushes to the output layer (1→1.08) as an event push; shot 1's constant-speed slow push (1→1.025) around the grid is the old pattern — don't copy it in new films.
- **Hold still on wait**: In the original work, wait periods are usually **static** — this is the biggest difference from launch-event films. Don't add constant-speed slow-push, breathing, or floating to fill movement; dynamism comes from the next Transform.

## ④ Transitions (4 common types)

1. **Transform continuation (no cut)**: the last frame of the previous shot = the first frame of the next shot; morph transforms the old object into the new one. This film, shot 1→2: 100 pixel grids become a column of input neurons; shot 2's first frame is pixel-by-pixel identical to shot 1's last frame. This is 3b1b's primary transition, used the vast majority of the time.
2. **Zoom-through**: the camera pushes in toward an object exponentially (`zoom = Z^e`, constant perceived speed); the object's circumference becomes an opening, and the new scene is inside. `TRANSITIONS.zoomThrough`, parameters `live:true` (old shot keeps pushing the camera past duration, vector redraw prevents blur), `r0` (object radius), `zoom ≥ 1100/r0` (otherwise the opening doesn't fill the screen, last frame jumps), `focus` (new scene's main subject starts at the center of the opening, snaps to position after e>0.55). This film, shot 2→3: first tint the hidden neuron with activation 0.95 yellow ("let's look at this one"), then push in 48×, 0.75 s.
3. **FadeOut(shift=UP) + FadeIn(shift=UP)**: on topic change, everything fades upward; new content fades in from below (`TRANSITIONS.fadeShift`).
4. **ReplacementTransform for title/formula**: symbols in the old formula move to the positions of same-name symbols in the new formula (TransformMatchingTex, 3b1b version default 2 s); unmatched symbols fade out and in.

## ⑤ Rhythm and text

- **Shot duration**: The original is a continuous scene — individual animations 1–3 s, then wait 1 s; one "shot" (one concept) is commonly 8–20 s. This film's 8 s with 3 shots (2.6/2.8/2.6 s) is a **compressed version**; for real voiceover use, stretch 2–3×.
- **Syncing with voiceover**: Grant's workflow is **animate first, record voiceover second** ("I start by laying out all of the animations… then once I record the voiceover, the actual editing is like a day"). So the sync rule is "one sentence = one animation": the animation starts when the action verb is spoken, then wait ≈1 s after the sentence ends for the audience to look.
- **Text**: title/question is Written before the action (question first, then demonstrate); formula and scene appear simultaneously, in the same color; numerical values (0.95) count up with the fill, not before the scene appears. No more than one title line + one annotation line on screen in Chinese at once.
- **FAQ principle**: "Every movement on the screen should be deliberate, with an identifiable purpose" — delete any motion that has no explanatory purpose.

## ⑧ The 3 most common mistakes

1. **Treating "glow" as a 3b1b signature and adding bloom or a deep-blue gradient background.** The original is pure black + high-saturation thin lines + ×1.5 saturation, almost no halo. Adding halos turns it into a "tech-style PowerPoint."
2. **Using linear or ordinary ease throughout, with animations too fast and too many.** The default must be smooth (quintic polynomial), each animation 1–3 s then pause 1 s; every motion should correspond to a verb in the voiceover.
3. **Changing the color encoding mid-film or using too many colors.** One color = one concept; symbol in the formula and object in the scene share the same color. More than 3–4 semantic colors and the audience can't keep track.
